# ai-plus-prompt

> [English](README.en.md) | 简体中文

一套面向 LLM 的**推理协议工程**，封装为可直接安装的 Agent Skill。核心是一个双模式自适应协议：日常对话保持自然，硬约束问题自动进入四阶段极限推理——**切换是隐式的，输出不留任何协议痕迹**。

## 项目结构

```
ai-plus-prompt/
├── README.md                    # 中文说明（本文件）
├── README.en.md                 # English documentation
├── LICENSE                      # MIT License
├── index.html                   # 项目介绍页
└── skills/
    └── adaptive-thinking-protocol/
        ├── SKILL.md             # 协议主体（英文，约 136 行）
        └── references/          # 示例库（加载时全量读取，约 1430 行）
            ├── mode-routing.md          # 模式判定：4 问测试 + 40 例 + 8 个边界案例
            ├── mode-a-playbook.md       # 模式 A 实战：正反例对照
            ├── mode-b-walkthroughs.md   # 模式 B 四阶段完整推演 × 4
            ├── insufficient-conditions.md # 三重门槛：5 通过 / 6 驳回
            ├── anti-patterns.md         # 12 种崩坏模式诊断
            ├── domain-recipes.md        # 5 大领域的分阶段特化

```

协议全文只有一个来源：`SKILL.md`。不存在与它并行的「中文原文」文件——多一份副本就多一处会漂移的地方。

## 核心设计

### 双模式

| | 模式 A：常规对话（默认） | 模式 B：极限推理 |
|---|---|---|
| **触发** | 闲聊、情感、常识科普、创意发散、简单问答 | 数学证明、代码 Debug、逻辑推演、约束规划、多变量冲突、自指悖论，以及任何带"禁止/必须/最优化/证明"的硬约束 |
| **执行** | 自然、流畅、直接；可追问、可调侃、可承认不知道 | 四阶段**内部**完成，输出只保留必要逻辑链 |
| **输出** | 禁止阶段标签、假设表、公式堆砌 | 结论 + 约束覆盖度自检，禁止自然语言试错叙述 |

### 四阶段骨架（模式 B）

1. **形式化与极值探测**——先转公式/变量/状态空间，算全局不变量与上下界。**未完成极值探测前，禁止构造具体实例。**
2. **假设树与最小冲突集**——候选路径 H1/H2… 各附置信度与推翻条件，明确声明放弃的路径及原因。
3. **对抗性推演与合规审查**——为每个结论构造反例，执行字面合规 + 意图合规双重审查。
4. **结构化输出**——结论 + 约束覆盖度自检。

### 三重门槛：什么时候才允许说"条件不足"

三个条件**同时**满足才可输出"条件不足 / 无法确定"：

1. 已进入模式 B；
2. 阶段二的假设树中，所有候选路径的推翻条件均无法被题干排除；
3. 已穷尽题面明示信息与标准学科公理，仍无唯一解。

否则一律不许以该句搪塞——尤其禁止用它回避计算、回避歧义判定，或因懒得深究而提前退出。

### 编码规则

只要回复里包含会被保存的代码，无论处于哪个模式，都适用同一套编写规则：

1. **统一使用 Doc 注释，不用裸注释。** 每个可被调用、导入或配置的符号都要有文档注释——语法跟随宿主语言的文档工具（`/** */`、`"""`、`///`、`/// <summary>`、Go 的声明上方 `//`），但**结构统一**：一行摘要、空行、参数、返回值、失败模式。裸 `//` 和 `#` 只能用于实现说明，不能作为公开符号的唯一文档。
2. **按种类分组，不按时间顺序。** 导入 → 常量 → 类型 → 模块级变量 → 私有辅助函数 → 公开函数 → 类 → 入口。变量和变量放一起，函数跟函数放一起；函数内部同理：先守卫子句，再主流程，最后副作用。
3. **排版统一。** 顶层声明之间空两行，逻辑块之间空一行，括号内不空行；一行一条语句；无行尾空格，不混用制表符与空格；长行在参数边界折行。
4. **格式化工具优先。** 项目有 formatter 配置时，它的输出就是"美观"的定义；与周边代码风格冲突时，跟随周边代码；**绝不重排未修改的行**。

十二种语言的注释语法对照、标准文件布局、一份改写前后的完整示例、以及提交前检查清单，都在 `coding-rules.md`。

### 为什么示例比协议本身更重要

协议条文能背下来，但"阶段一真的算出了上下界"和"阶段一写了一句看起来像形式化的话"是两回事。示例库的作用是提供**可对照的完成标准**：

- 阶段一必须产出一个**与最终答案无关**的界（整除证明里先得到 d ≤ 6，证明才成立）；
- 阶段二必须至少有一条**真的被放弃**的路径；
- 阶段三必须找到**会真正击穿结论**的那个反驳，而不是象征性的自查；
- 阶段四的输出必须**短于**推导过程。

## 快速开始

### 方式一：安装为 Skill（推荐）

1. 把 `skills/adaptive-thinking-protocol/` 整个目录复制到 `~/.workbuddy-ai/skills/`。
2. 刷新技能列表，技能即被识别。
3. 正常提问即可——协议加载后对**本会话后续每一条回复**持续生效，无需重复声明。

### 方式二：提取为 System Prompt

如果目标环境不支持 Skill，可以直接取 `SKILL.md` 里从标题到 `## 5. Code Authoring` 之间的内容，粘贴为 System Prompt：

1. 打开 `skills/adaptive-thinking-protocol/SKILL.md`。
2. 复制 `# Full-Scenario Adaptive Thinking Protocol V1.1.5` 到 `## 5. Code Authoring` 末尾的正文。
3. 去掉 YAML frontmatter 与 `Reference Map` 两节——前者是技能元数据，后者指向的 `references/` 在纯 Prompt 环境下不存在。

注意：这个形态**不含**示例库，只保留协议条文，效果等同于协议的最小可用版本。

## 设计取舍

**为什么协议里多了一节 `Activation and Persistence`？**
System Prompt 天然全程生效，而 Skill 是**按需加载**的。如果不显式声明"加载后对整个会话持续生效、静默运行、不向用户解释协议本身"，模型很可能只在触发那一轮遵守协议。该节不含任何新的推理规则，只负责锁定作用域。

**为什么删掉了中文原文 `1.1.5.md`？**
因为它和 `SKILL.md` 是同一份协议的两个副本。两份并存的代价不是多占一点空间，而是**必然漂移**——改了一边忘了另一边，读者也无从判断哪份是准的。现在协议只有一个来源，`README.md` 和 `README.en.md` 只做说明，不再承载协议正文。需要中文对照时看 git 历史即可。

**为什么禁止输出阶段标签，却又要求逻辑可还原？**
标签是给写作者看的，不是给读者看的。读者需要的是逻辑链，不是推导过程的转录。两条规则合起来的效果是：答案读起来像深度思考的结果，而不像思考过程的记录。

**为什么"条件不足"要设三重门槛？**
因为这句话能终止任务，所以它是任何压力下最短的出路。而门槛真正打开时，诚实答案通常也不是"不知道"，而是**精确刻画**——空集、区间、解族、下确界不存在。`insufficient-conditions.md` 里 5 个通过案例全部以结构性结论收尾，没有一个是"我不知道"。

**为什么加载时要读全部子文件，而不是只读 `SKILL.md`？**
因为只读 `SKILL.md` 会得到一个**术语完整但纪律缺失**的版本——它知道"阶段一""假设树""三重门槛"这些词，却不知道一个合格的阶段一长什么样。示例库里放的全是"什么算做完了"的判据，这些判据没法压缩进条文。所以 `SKILL.md` 里加了 Bootstrap 一节，要求加载后先读完七份再回答第一个实质问题，并规定读完后不要向用户复述、不要提这件事。代价是上下文占用上升，这是明知的选择。

**为什么删掉了 V1.1.0？**
V1.1.0 是单一强制模式，所有任务一律走重推理并强制外显全部推导。它把"推理强度"和"输出格式"绑死了——想要深度就必须牺牲对话体验。V1.1.5 把这两件事解耦：推理深度由模式 B 保证，输出格式由模式决定。单协议比双版本维护成本更低，覆盖面更广。
