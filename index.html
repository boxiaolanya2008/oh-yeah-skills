oh-yeah-skillsAgent Skill全场景自适应思考协议

同一套提示词，
两种完全不同的回答方式。

一个双模式自适应推理协议。日常对话保持自然，硬约束问题自动进入四阶段推理——切换是隐式的，输出里看不到任何协议痕迹。

模式 A

常规对话

今天好累。

累了。是活儿堆到一起了，还是那种什么都还行、但就是提不起劲的日子？

模式 B

极限推理

证明 n³−n 能被 6 整除。

n³−n = n(n−1)(n+1)，三个连续整数之积。 2 与 3 互素，分别验证：三者中必有一个偶数；n mod 3 的三种情形下必有一个被 3 整除。故 6 整除它。 n = 2 时值为 6，故 6 是最紧的界，不能加强到 12。

一它解决什么问题

默认状态下的模型有四种可预测的失效，而且它们互相关联：

  • 01 模式错配。该闲聊时给出四点建议清单，该证明时给出一段结论摘要。同一套语气用在所有场合。
  • 02 推理不可检验。答案读起来很笃定，但没有一行可以被指出来说"这一步错了"。它会在错误的情况下也照样成立。
  • 03 「信息不足」成了最短出口。这句话能直接终止任务，所以在任何压力下它都最先出现——哪怕问题只是需要算一下，或者只需要反问一句。
  • 04 长会话衰减。前五轮很好，到第十五轮时标题又回到了闲聊回复里，协议被上下文挤掉了。

协议的四个设计分别对应这四种失效，没有一条是装饰性的。下面逐条说明。

二两种模式

每一条回复发出之前，先对输入做意图判定，再选择执行路径。这是唯一一个在每一轮都要做的决定。

模式 A · 常规对话（默认）模式 B · 极限推理
触发 闲聊、情感交流、常识科普、创意发散、简单事实问答 数学证明、代码 Debug、逻辑推演、约束规划、多变量冲突、自指悖论，以及任何带「禁止 / 必须 / 最优化 / 证明」的硬约束
执行 自然、流畅、直接；可追问、可调侃、可承认不知道 四阶段在内部完成，输出只保留必要逻辑链
输出 禁止阶段标签、假设表、公式堆砌 结论加约束覆盖度自检；禁止自然语言试错叙述

判定的关键是问一句：这个答案能不能被判定为错？能，就走模式 B。不能，就走模式 A。所以"解释为什么我的代码崩溃"是模式 A——原因已知；"找出我的代码为什么崩溃"是模式 B——原因未知且必须推导出来。

切换是隐式的。不需要用户声明，输出里也不会出现"我现在切换到模式 B"这类话。读者只会感觉到这一轮回答的分寸变了。

三四阶段推理骨架

进入模式 B 后，以下四步在内部严格按序执行。顺序不可打乱，不可融合。

  1. 形式化与极值探测

    先把问题转成公式、变量或状态空间，算出全局不变量与上下界。阻断规则：未完成极值探测前，不得构造具体实例。

  2. 假设树与最小冲突集

    列出候选路径 H1、H2……，每条附上置信度与推翻条件，并明确声明放弃的路径及原因。没有一条被真正放弃的假设树，等于没做这一步。

  3. 对抗性推演与合规审查

    为每个结论构造反例，找出会击穿结论的那一个，而不是象征性自查。发现前序错误时标记回溯，从最近正确节点重算。

  4. 结构化输出

    给出结论与约束覆盖度自检。严禁自然语言试错描述（"如果把它往右移……"），输出必须短于推导过程。

阶段一为什么必须产出界？因为界与最终答案无关。整除证明里先算出 d ≤ 6，证明才存在；如果阶段一的第一行就已经写着答案，那四步是被合并了，只是看起来完整。

四三重门槛：什么时候才允许说「条件不足」

三个条件必须同时成立。点一下，看看门槛是怎么关着的。

未满足 不允许以「条件不足」收尾。必须继续算，或者反问一句补上缺失的输入。

门槛真正打开时，诚实答案通常也不是「我不知道」。示例库里的五个通过案例全部以结构性结论收尾：空集、区间、解族、下确界不存在、参数化家族。没有一个是「无法确定」。

这句话能终止任务，所以它是任何压力下最短的出路。三重门槛的作用不是让人更谨慎，而是逼出那个更难的答案——把答案集合刻画清楚，而不是放弃刻画。

六编码规则：不分语言

只要回复里包含会被保存的代码，无论处于哪个模式，都走同一套规则。规则本身与语言无关，只有注释的语法随宿主语言变化。

规则要求反例
注释 公开符号一律用 Doc 注释，语法随语言：/** */、"""、///、/// <summary>、Go 的声明上方 // // retry 写在函数上方——只是重复了函数名
分组 导入 → 常量 → 类型 → 模块级变量 → 私有辅助函数 → 公开函数 → 类 → 入口。变量和变量放一起，函数跟函数放一起 一个常量夹在两个函数中间
同类语句 函数内部同理：先守卫子句，再主流程，最后副作用 校验写在它本该拦住的副作用之后
排版 顶层声明之间空两行，逻辑块之间空一行，括号内不空行；一行一条语句；无行尾空格 制表符与空格混用，一行塞两条语句
格式化工具 有 formatter 配置时它的输出就是标准；绝不重排未修改的行 顺手把整段缩进从 2 空格改成 4 空格

最后一条最容易被忽略，也最伤协作。一个顺手重排了无关空白的 diff，会把真正的改动藏起来——评审的人要多花的时间，远超过格式化省下的那点力气。

七具体提升了什么

不谈抽象的好处，只看同一个问题前后两种答法。

场景默认状态加载协议后
闲聊 四点建议清单，末尾问"需要我展开吗" 一句话接住，再问一个具体的问题
数学证明 描述这个证明，没有可检验的步骤 先算界，再给可逐步验证的推导，并说明界是最紧的
代码报错 罗列五种可能原因 找出最小反例定位机制，并排除其他三种可能
产出代码 能跑就行，函数和常量混在一起，注释只是重复函数名 Doc 注释写清前置条件与失败模式，按种类分组，排版统一
信息不全 「信息不足，无法确定」 刻画答案集合的形状，并指出缺哪一个约束
最优化问题 给出一个可行方案 给出方案，并证明没有更优解
长对话 逐渐退回默认语气 静默维持，且不向用户解释协议本身

代价

说清楚成本比只讲收益可信。三件事需要知道：

  • — 上下文占用。七份示例库合计约 1430 行，加载时全量读入，确实会挤占上下文。这是明知的选择——只读 SKILL.md 会得到术语而没有纪律。长会话里如果上下文吃紧，可以改为只读索引表指定的那一份。
  • — 判定本身会出错。模式 A/B 的边界不是总能一刀切开。判错的代价不对称：误判成 B 只是啰嗦，误判成 A 会让证明变成空话。routing 文档里 8 个边界案例就是为这个准备的。
  • — 它不提升知识量。协议改变的是推理纪律和输出形态，不是模型知道什么。知识边界之外的问题，它一样答不出来——只是会更早地承认这一点。

八安装

整个技能是一个自包含目录，复制过去即可。

cp -r skills/adaptive-thinking-protocol ~/.workbuddy-ai/skills/

装好后的结构：

~/.workbuddy-ai/skills/adaptive-thinking-protocol/
├── SKILL.md              协议主体，约 136 行
└── references/           示例库，7 份，约 1430 行

刷新技能列表后即可使用。协议加载后对本会话后续每一条回复持续生效，不需要重复声明，也不会在输出里提到自己。

如果目标环境不支持 Skill，也可以把 SKILL.md 里从标题到 ## 5. Code Authoring 的正文提取出来，去掉 YAML frontmatter 和 Reference Map 两节，粘贴为 System Prompt。这个形态不含示例库，是协议的最小可用版本。
